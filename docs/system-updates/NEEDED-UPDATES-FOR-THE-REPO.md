## 1. ❌ Failing test (fix first — 2 min)

### 1.1 Stale envelope assertion in `_test-escrow-wiring.ts`

- **Where:** `scripts/_test-escrow-wiring.ts:142`
- **What:** The assertion expects `{ error: "wishlist_not_found" }` exactly, but the Day-5 hardening added `request_id` to every response envelope. The test was never updated.
- **Why this matters:** `npm run test:escrow-wiring` currently reports `10 passed, 1 failed`. CI/regression coverage of the error envelope is broken.
- **Fix:**
  ```ts
  // line 142 — change from:
  assert.deepEqual(body, { error: "wishlist_not_found" });
  // to:
  assert.equal(body.error, "wishlist_not_found");
  assert.match(body.request_id, /^[0-9a-f-]{36}$/);
  ```

## 3. 🔴 High — production-safety bugs

These do not block the testnet demo, but each is a real defect that would surface in a mainnet deployment.

### 3.1 Contract panics use `&str` instead of `Symbol`

- **Where:** `internstellar-contract/contracts/internstellar/src/lib.rs` — every `panic!(...)` call (lines 50, 53, 102, 108, 114, 153, 161, plus `expect()` strings on 74, 75, 76, 120, 123, 175).
- **What:** 13 `panic!("string literal")` calls.
- **Why this matters:** Violates the project's own rule in `CLAUDE.md`: *"Never use standard string slices (`&str`) in contract panic macros to avoid WASM allocation errors. Use `Symbol`."* Works on testnet today, but bloats WASM and risks host allocation failure under stricter mainnet limits.
- **Fix shape:**
  ```rust
  use soroban_sdk::{panic_with_error, contracterror};

  #[contracterror]
  #[derive(Copy, Clone, Debug, PartialEq, Eq)]
  #[repr(u32)]
  pub enum Error {
      TotalNotPositive    = 1,
      PctNotHundred       = 2,
      EscrowAmountNotPos  = 3,
      FamilyEqualsStore   = 4,
      InsufficientGroc    = 5,
      EscrowNotFound      = 6,
      EscrowAlreadyReleased = 7,
      // …
  }

  // replace:
  panic!("total must be positive");
  // with:
  panic_with_error!(&env, Error::TotalNotPositive);
  ```
  Then update `lib/stellar/contract.ts` `KNOWN_PANIC_STRINGS` to map error codes → human messages.
- **Effort:** 1-2 hours + one contract redeploy.

### 3.2 No `extend_ttl` on persistent storage

- **Where:** `lib.rs:78-80, 125-129, 165, 176` — all `env.storage().persistent().set(...)` calls.
- **What:** Persistent entries are written but never have their TTL extended.
- **Why this matters:** Soroban persistent storage charges rent and auto-archives entries past their TTL. On testnet the windows are generous; on mainnet a locked escrow could be archived before the family confirms delivery, requiring a `restore` op (extra fee + UX hit) before release works.
- **Fix shape:** After each `set(...)` on a long-lived key (escrow rows, bucket balances), call:
  ```rust
  env.storage().persistent().extend_ttl(&key, /* threshold */ 100, /* extend_to */ 4096);
  ```
- **Effort:** 30 min + redeploy.

### 3.3 Escrow ID stashed in user-editable `wishlist.notes`

- **Where:**
  - Lock route stashes: `app/api/escrow/lock/route.ts:216-218`
  - Release route extracts: `app/api/escrow/release/route.ts:30-39, 125-126`
  - Schema: `db/schema.sql:45-57` (no `escrow_id` column)
- **What:** The on-chain `u32` escrow id returned by `lock_escrow` is appended to `wishlist.notes` as the marker string `__escrow_ret__:<id>`. On release the route regex-extracts it back.
- **Why this matters:** `notes` is a **user-facing free-text field** ("Lola needs her maintenance meds"). If the family edits notes after lock — through any current or future UI path — the marker can be lost or mangled, and the release path silently breaks.
- **Fix:**
  1. Add a column:
     ```sql
     alter table wishlist add column escrow_id bigint;
     ```
  2. In `app/api/escrow/lock/route.ts`, update `escrow_id` directly instead of stuffing it into `notes`.
  3. In `app/api/escrow/release/route.ts`, read `wishlist.escrow_id` directly and remove `extractStashedEscrowId()`.
- **Effort:** 30 min including migration + smoke test.

### 3.4 Release fallback uses tx hash as escrow id

- **Where:** `app/api/escrow/release/route.ts:126`
  ```ts
  const escrowId = stashed ?? wishlist.escrow_tx_hash;
  ```
- **What:** If `__escrow_ret__` is missing from `notes`, the code falls back to the 64-hex transaction hash and passes it to `releaseEscrow({ escrowId })`. The contract bridge expects a `u32` and throws an opaque error.
- **Why this matters:** Confusing failure mode that surfaces as a generic `contract_error` instead of "escrow id not recorded — DB drift." Goes away with fix 3.3.
- **Fix:** Replace the fallback with an explicit error:
  ```ts
  if (wishlist.escrow_id == null) {
    return err(409, "escrow_id_missing",
      "Lock recorded but escrow_id was not captured. Reconcile from settlement.",
      undefined, { requestId });
  }
  const escrowId = wishlist.escrow_id;
  ```

## 4. 🟡 Medium — scaling / multi-tenant readiness

Acceptable for the single-family-single-store demo. Each becomes a real bug at multi-tenant scale.

### 4.1 OFW can act on any family

- **Where:** `app/api/escrow/lock/route.ts:68-86`, `app/api/escrow/release/route.ts:80-93`, `app/(app)/ofw/page.tsx:31-37`, `app/(app)/ofw/actions.ts:17`
- **What:** Auth check accepts the caller if they are the family **or** any user with role `ofw`. There is no schema-level OFW→family link.
- **Why this matters:** With multiple families, any OFW account could lock/release escrows against any family's wishlist. Documented in code with three `TODO(P4)` markers.
- **Fix:**
  1. Add the link column:
     ```sql
     alter table profiles add column sponsor_ofw_id uuid references profiles(id);
     create index profiles_sponsor_ofw_idx on profiles(sponsor_ofw_id);
     ```
  2. Tighten the routes:
     ```ts
     if (callerProfile?.role === "ofw") {
       const { data: f } = await supabase.from("profiles")
         .select("sponsor_ofw_id").eq("id", family_id).maybeSingle();
       if (f?.sponsor_ofw_id !== caller.userId) {
         return err(403, "forbidden", "OFW is not linked to this family.",
           undefined, { requestId });
       }
     }
     ```
- **Effort:** 1 hour including migration + tests.

### 4.2 Idempotency is in-memory per-process

- **Where:** `lib/api/idempotency.ts:24` — `const inFlight = new Map<...>();`
- **What:** The dedup map lives in Node process memory.
- **Why this matters:** Behind a load balancer, two Next.js instances each maintain their own map → identical concurrent requests can pass the guard on different instances and produce double on-chain calls.
- **Fix options:**
  - Move to Redis (`SET NX EX 60`) keyed on the same sha256.
  - Or rely on Postgres advisory locks via Supabase.
- **Effort:** 1 hour.

### 4.3 `deposit_and_split` percentage sum can overflow before check

- **Where:** `lib.rs:52`
  ```rust
  if pct_util + pct_groc + pct_emerg != 100 { ... }
  ```
- **What:** Three `u32`s are added before the inequality check. With overflow-checks on (release default), an adversarial caller crashes the contract; off, the sum wraps and could equal 100.
- **Fix:**
  ```rust
  let sum = pct_util
      .checked_add(pct_groc).and_then(|s| s.checked_add(pct_emerg))
      .unwrap_or_else(|| panic_with_error!(&env, Error::PctNotHundred));
  if sum != 100 {
      panic_with_error!(&env, Error::PctNotHundred);
  }
  ```
- **Effort:** 10 minutes + redeploy. Bundle with item 3.1.

## 5. 🟢 Low — housekeeping

### 5.1 `.env.example` ships a real-looking secret (demo-blocker per policy)

- **Where:** `.env.example:40`
  ```
  STELLAR_DEMO_SECRET_KEY=SDWT2IYMTVTTGD46WCILWFUHBKGMWFQHYANRW6ARZXQRKL7VRB3PKQAM
  ```
- **What:** CLAUDE.md mandates `.env.example` be placeholders only. A real-looking testnet secret is checked in.
- **Why this matters:** Even on testnet, this trains the team to commit secrets. If it is meant to be a shared demo signer, it should be documented as such; if it is a personal keypair, it should be rotated.
- **Fix:** Replace the value with `S` × 56 placeholder and add a one-line note:
  ```
  # Generate one with: npm run fund-test-account
  STELLAR_DEMO_SECRET_KEY=
  ```

### 5.2 Permissive `any` casts in dashboard data shaping

- **Where:** `lib/dashboard/family.ts`, `lib/dashboard/ofw.ts`, `lib/dashboard/store.ts` — ~25 `(row as any).inventory[0]`-style casts.
- **What:** Supabase nested-join responses return either arrays or single objects depending on FK shape; the code casts to `any` to handle both.
- **Why this matters:** Type safety holes in the data layer. Not a runtime bug today, but a regression risk if Supabase response shapes change.
- **Fix:** Run `npx supabase gen types typescript --project-id <id> > lib/database.types.ts` and replace `any` with the generated `Database` types. Optional but recommended.
